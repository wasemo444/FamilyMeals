## Architectural Pattern: Ports and Adapters

The codebase follows a **hexagonal** layout:

| Port (Shared) | Api Adapter | Client Adapter |
|---------------|-------------|----------------|
| `IContentDataService` | `ContentDataService` | `ApiContentDataService` |
| `IAppDataStore` | `EfAppDataStore` | — |
| `IOwnershipAuthorization` | `OwnershipAuthorizationService` | — |
| `IAuthClient` | — | `AuthClient` / `WebHostAuthClient` |
| `IGroupService` | — | `GroupClient` |

**Pure domain rules** (`ContentDataQueries`, `OwnershipRules`) have no I/O and are shared by both `ContentDataService` and `ApiContentDataService`.

## Authentication & Session

### Two Login Paths (Web)

| Path | Endpoint | Host | Used By |
|------|----------|------|---------|
| Browser form | `POST /account/login` | Web (:5084) | Login.razor HTML form |
| JSON API (cookie) | `POST /api/auth/login` | Api (:5280) | `AuthClient`, tests, E2E API login |

Both web paths issue the same cookie name (`.LinkNest.Auth`) when DataProtection keys are shared.

### Mobile Login Path (JWT)

| Path | Endpoint | Used By |
|------|----------|---------|
| Token login | `POST /api/auth/token` | MAUI `AuthClient.LoginWithTokenAsync` |

Returns `AuthTokenResponse` (`accessToken`, `expiresAtUtc`, `user`). Token stored in `MauiSecureTokenStore` (SecureStorage); attached via `BearerTokenHandler`. Logout is **client-side only** (clear store) — `/api/auth/logout` signs out cookies, not JWTs.

### SmartAuth (Api)

`IdentityServiceExtensions` registers a **SmartAuth** policy scheme: requests with `Authorization: Bearer` forward to JWT validation; otherwise cookie auth. Same protected endpoints serve web and mobile.

```
Authorization: Bearer …  →  JwtBearer  →  UserManager.GetUserAsync
Cookie .LinkNest.Auth    →  Identity cookie scheme
```

### Cookie Forwarding (Web only)

Blazor components call same-origin `/api/*`. `CookieForwardingHandler` copies the browser `Cookie` header onto outbound proxy requests so the Api sees the authenticated user.

```
Browser cookie  →  Web YARP  →  CookieForwardingHandler  →  Api Identity middleware
```

### WASM Auth Handoff

Web registers `AddAuthenticationStateSerialization`; Client registers deserialization. `PersistingRevalidatingAuthenticationStateProvider` revalidates the user every 30 minutes via `UserManager`.

### Logout CSRF

`POST /account/logout` validates same-origin via `Origin` or `Referer` header (`AccountEndpoints.IsSameOriginFormPost`). Cross-site form posts are rejected with 400.

### Rate Limiting

Auth JSON endpoints on Api use a fixed-window limiter (`20/min` production, `1000/min` in `Testing`).

### Key Types

- `IdentityServiceExtensions` — SmartAuth, cookie + JWT, DataProtection, Identity setup
- `JwtTokenService`, `ConfigureJwtOptions`, `ConfigureJwtBearerOptions` — JWT minting/validation
- `AccountEndpoints` — form login/logout on Web
- `AuthEndpoints` — JSON register/login/**token**/logout/me on Api
- `WebHostAuthClient` — uses local `SignInManager` when `HttpContext` present
- `PersistingRevalidatingAuthenticationStateProvider` — SSR/WASM bridge (web)
- `JwtAuthenticationStateProvider`, `BearerTokenHandler`, `UnauthorizedSessionHandler` — mobile/shared bearer pipeline
- `IClientAuthMode`, `ISecureTokenStore`, `IAuthStateNotifier` — platform auth abstractions

## Content Data Subsystem

### Read Model: Bootstrap Snapshot

`GET /api/bootstrap` returns an `AppData` JSON payload:

- Categories and links **scoped** to current user + group memberships
- App settings (culture code)
- Each entity includes `RowVersion` for optimistic concurrency

The Blazor client caches this in `ApiContentDataService._cache` and reloads after every mutation.

### Write Path

```
Page → ApiContentDataService → POST/PUT /api/... → ContentDataLoadMiddleware
  → ContentDataService → EfAppDataStore.SaveAsync → PostgreSQL
  → ApiContentDataService.ReloadFromServerAsync (GET /api/bootstrap)
  → DataChanged event → UI refresh
```

### ContentDataLoadMiddleware

Pre-calls `IContentDataService.EnsureLoadedAsync()` for most `/api/*` routes so handlers operate on loaded in-memory state.

**Skipped routes:** bootstrap, auth, groups list/create, settings, link-preview.

### In-Memory Server Cache

`ContentDataService` (Api) holds `_data` for the request scope. Multiple endpoint calls in one request share the same loaded snapshot.

### Archive Policy

- Archive = soft delete (`IsDeleted`, `DeletedAtUtc`)
- Retention: **7 days** (`ArchivePolicy.RetentionDays`)
- `ArchiveMaintenanceService` purges expired items at startup
- Archiving a category also archives its active links

### Concurrency

Updates require client `RowVersion`. `EfAppDataStore` throws `ConcurrencyConflictException` on stale/missing tokens → `ConcurrencyConflictExceptionHandler` → **HTTP 409**.

`ApiContentDataService` maps 409 to `ConcurrencyConflictException` on the client.

### Key Types

- `IContentDataService` / `ContentDataService` / `ApiContentDataService`
- `ContentDataQueries` — pure read filters (favorites, active, archived, search scopes)
- `EfAppDataStore` — EF load/save with ownership filter
- `BootstrapEndpoints` — snapshot endpoint
- `ArchiveMaintenanceService` — purge job

## Ownership & Groups

### Owner Types

| `OwnerType` | Meaning | Stored on |
|-------------|---------|-----------|
| `User` | Personal content | `OwnerUserId` |
| `Group` | Shared with group members | `OwnerGroupId` |

CHECK constraints (`OwnershipConstraintSql`) enforce valid combinations at the database level.

### Three-Layer Authorization

1. **`OwnershipRules`** (Shared, pure) — `CanMutate`, `ValidateCreateOwner`, `MatchesFilter`
2. **`IOwnershipAuthorization`** (Api) — loads member group IDs from DB
3. **`EfAppDataStore`** — filters load/save to accessible entities only

### Security Semantics

Unauthorized mutation attempts return **404 Not Found** (not 403) to avoid leaking resource existence. Applies to category/link archive, restore, favorite, create in inaccessible groups.

### ContentOwner Resolution

`ContentOwner.TryResolve(ownerType, ownerGroupId, …)` validates create requests:

- `ownerType=Group` without `ownerGroupId` → **400 Bad Request**
- Non-member group → **404** on create and name-available checks

### Home Content Filter

`HomeContentFilter` enum: `All`, `Mine`, `Shared`. Applied in `ContentDataQueries.GetActiveCategories` / `GetFavoriteCategories`.

### Group API

- `POST /api/groups` — create group; creator becomes Admin
- `GET /api/groups` — list all groups the current user belongs to (multi-group supported)

See [Group Membership (E5)](#group-membership-e5) for invite/leave/remove endpoints.

### Legacy Backfill

`OwnershipBackfillService` at startup assigns orphan rows (both owner columns null):

1. Categories → default/earliest user
2. Links → inherit parent category ownership via SQL join

### Key Types

- `OwnershipRules`, `IOwnershipAuthorization`, `OwnershipAuthorizationService`
- `ContentOwner`, `HomeContentFilter`, `GroupSummary`
- `GroupEndpoints`, `GroupMembershipEndpoints`, `GroupMembershipService`, `OwnershipBackfillService`
- `ContentCategoryEntity`, `SavedLinkEntity`, `GroupEntity`, `GroupMembershipEntity`, `GroupInviteEntity`

## Group Membership (E5)

### Rules

| Rule | Enforcement |
|------|-------------|
| **Max 10 members per group** | `GroupPolicy.MaxMembers`; checked on invite and accept |
| **Invite-only join** | Admin sends email invite to registered user; no public discovery |
| **Content orphaning** | Leave/remove deletes `GroupMembership` only; group-owned categories/links remain |
| **Admin-only invite/remove** | Non-admins get 404 on invite/remove endpoints |
| **Duplicate membership** | Accept rejects if user is already a member of the target group |

### Invite Flow

```
Admin → POST /api/groups/{id}/invites { email }
  → Invitee must be a registered user with confirmed email (when RequireConfirmedEmail)
  → 400 + code on failure: invitee_not_found, invitee_email_unconfirmed, group_full, invitee_in_group, etc.
  → GroupInviteEntity (Status=Pending)
Invitee → GET /api/groups/invites/pending (Home UI)
Invitee → POST /api/groups/invites/{id}/accept
  → GroupMembership (Role=Member) + invite Status=Accepted
  → Invitee can now see group shared content (E4 bootstrap scoping)
```

Decline: `POST /api/groups/invites/{id}/decline` → Status=Declined.

### Leave / Remove

| Action | Endpoint | Who |
|--------|----------|-----|
| Leave | `POST /api/groups/{id}/leave` | Any member (including admin) |
| Remove | `DELETE /api/groups/{id}/members/{userId}` | Admin only; cannot remove self |

After leave/remove, user loses access to group content on next bootstrap reload; group-owned data persists.

### Key Types

- `GroupMembershipService` — cap, admin/member, duplicate-membership checks
- `GroupMembershipEndpoints` — HTTP surface
- `GroupInviteEntity`, `GroupInviteStatus`, `GroupInviteSummary`
- `GroupMemberSummary`, `GroupPolicy`
- `IGroupService` / `GroupClient` — client adapter
- `GroupMembers.razor` — `/group/{groupId}` UI

### Tests

`tests/LinkNest.Tests/Api/GroupMembershipEndpointsTests.cs`

| GET | `/bootstrap` | Full scoped `AppData` snapshot |

| POST | `/categories/{id}/archive` | Soft delete |
| POST | `/categories/{id}/restore` | Restore from archive |
| POST | `/categories/{id}/favorite` | Toggle favorite |

### Links (`LinkEndpoints`)

| Method | Route | Description |
|--------|-------|-------------|

## Blazor UI

### Render Modes

| Page | Mode | Notes |
|------|------|-------|
| `Home.razor` | `InteractiveServer` | Categories, filters, create category/group |
| `Groups.razor` | `InteractiveServer` | List groups, create group, pending invites at `/groups` |
| `GroupMembers.razor` | `InteractiveServer` | Member list, invite, remove, leave at `/group/{id}` |
| `Category`, `Share`, `Archive` | `InteractiveAuto` | Server first, may hydrate WASM |
| `Register.razor` | `InteractiveServer(prerender: false)` | Avoid auth mismatch |
| `Login.razor` | Static SSR | Plain HTML form, no `@rendermode` |

### InteractiveShell Gate

`InteractiveShell` blocks child content until:

1. User authenticated
2. `ApiContentDataService.InitializeAsync()` completes
3. `CultureService.InitializeAsync()` completes

Subscribes to `ApiContentDataService.Unauthorized` → redirect to `/login`.

### Localization

- Server: `UseRequestLocalization` (en, ar)
- Client: `CultureService` persists culture via `/api/settings`, sets RTL via JS interop
- Strings: `LocalizationCatalog` keyed by culture

### Component Patterns

- Pages inherit `LocalizedComponentBase` for `L["Key"]` accessor
- `CategoryCard` / `LinkCard` encapsulate favorite/archive actions
- Owner picker on Home/Share: personal vs group dropdown
- Home shows pending invites with accept/decline; link to **Manage members** → `/group/{id}`

### Client DI (`ClientServiceCollectionExtensions`)

Registers `ApiContentDataService`, `GroupClient`, `AuthClient`, `LinkPreviewClient`, `CultureService`, named `HttpClient "LinkNestApi"`.

## Known Tradeoffs & Gaps

| Topic | Current Behavior |
|-------|------------------|
| Client reload | Full bootstrap reload after every mutation (simple, not granular) |
| Client 409 handling | Exception thrown; no automatic retry UI |
| Settings path | `SettingsEndpoints` writes directly, not via full `AppData` snapshot merge |
| Invite code join | `InviteCode` on group exists; E5 uses email invite flow only |
| Mobile UI coupling | MAUI references Web.Client (Blazor WASM SDK); E9 H4 tracks `LinkNest.UI` extraction |
| JWT revocation | Logout is client-side; tokens valid until expiry |
| OpenAPI | No Swagger; use this doc + endpoint source |
| README | Updated for mobile; trust L1/L2 and epic tickets for latest |
