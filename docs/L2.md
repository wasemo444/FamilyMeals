## Architectural Pattern: Ports and Adapters

The codebase follows a **hexagonal** layout:

| Port (Shared) | Api Adapter | Client Adapter |
|---------------|-------------|----------------|
| `IMealDataService` | `MealDataService` | `ApiMealDataService` |
| `IAppDataStore` | `EfAppDataStore` | — |
| `IOwnershipAuthorization` | `OwnershipAuthorizationService` | — |
| `IAuthClient` | — | `AuthClient` / `WebHostAuthClient` |
| `IGroupService` | — | `GroupClient` |

**Pure domain rules** (`MealDataQueries`, `OwnershipRules`) have no I/O and are shared by both `MealDataService` and `ApiMealDataService`.

## Authentication & Session

### Two Login Paths

| Path | Endpoint | Host | Used By |
|------|----------|------|---------|
| Browser form | `POST /account/login` | Web (:5084) | Login.razor HTML form |
| JSON API | `POST /api/auth/login` | Api (:5280) | `AuthClient`, tests, E2E API login |

Both issue the same cookie name (`.ManageFamilyMeals.Auth`) when DataProtection keys are shared.

### Cookie Forwarding

Blazor components call same-origin `/api/*`. `CookieForwardingHandler` copies the browser `Cookie` header onto outbound proxy requests so the Api sees the authenticated user.

```
Browser cookie  →  Web YARP  →  CookieForwardingHandler  →  Api Identity middleware
```

### WASM Auth Handoff

Web registers `AddAuthenticationStateSerialization`; Client registers deserialization. `PersistingRevalidatingAuthenticationStateProvider` revalidates the user every 30 minutes via `UserManager`.

### Logout CSRF

`POST /account/logout` validates same-origin via `Origin` or `Referer` header (`AccountEndpoints.IsSameOriginFormPost`). Cross-site form posts are rejected with 400.

### Rate Limiting

Auth JSON endpoints on Api use a fixed-window limiter (`20/min` production, `1000/min` in `Testing`).

### Key Types

- `IdentityServiceExtensions` — cookie options, DataProtection, Identity setup
- `AccountEndpoints` — form login/logout on Web
- `AuthEndpoints` — JSON register/login/logout/me on Api
- `WebHostAuthClient` — uses local `SignInManager` when `HttpContext` present
- `PersistingRevalidatingAuthenticationStateProvider` — SSR/WASM bridge

## Meal Data Subsystem

### Read Model: Bootstrap Snapshot

`GET /api/bootstrap` returns an `AppData` JSON payload:

- Categories and links **scoped** to current user + group memberships
- App settings (culture code)
- Each entity includes `RowVersion` for optimistic concurrency

The Blazor client caches this in `ApiMealDataService._cache` and reloads after every mutation.

### Write Path

```
Page → ApiMealDataService → POST/PUT /api/... → MealDataLoadMiddleware
  → MealDataService → EfAppDataStore.SaveAsync → PostgreSQL
  → ApiMealDataService.ReloadFromServerAsync (GET /api/bootstrap)
  → DataChanged event → UI refresh
```

### MealDataLoadMiddleware

Pre-calls `IMealDataService.EnsureLoadedAsync()` for most `/api/*` routes so handlers operate on loaded in-memory state.

**Skipped routes:** bootstrap, auth, groups list/create, settings, link-preview.

### In-Memory Server Cache

`MealDataService` (Api) holds `_data` for the request scope. Multiple endpoint calls in one request share the same loaded snapshot.

### Archive Policy

- Archive = soft delete (`IsDeleted`, `DeletedAtUtc`)
- Retention: **7 days** (`ArchivePolicy.RetentionDays`)
- `ArchiveMaintenanceService` purges expired items at startup
- Archiving a category also archives its active links

### Concurrency

Updates require client `RowVersion`. `EfAppDataStore` throws `ConcurrencyConflictException` on stale/missing tokens → `ConcurrencyConflictExceptionHandler` → **HTTP 409**.

`ApiMealDataService` maps 409 to `ConcurrencyConflictException` on the client.

### Key Types

- `IMealDataService` / `MealDataService` / `ApiMealDataService`
- `MealDataQueries` — pure read filters (favorites, active, archived, search scopes)
- `EfAppDataStore` — EF load/save with ownership filter
- `BootstrapEndpoints` — snapshot endpoint
- `ArchiveMaintenanceService` — purge job

## Ownership & Groups

### Owner Types

| `OwnerType` | Meaning | Stored on |
|-------------|---------|-----------|
| `User` | Personal content | `OwnerUserId` |
| `Group` | Shared with group members | `OwnerGroupId` |

CHECK constraints (`OwnershipConstraintSql`) enforce valid combinations at the database level.

### Three-Layer Authorization

1. **`OwnershipRules`** (Shared, pure) — `CanMutate`, `ValidateCreateOwner`, `MatchesFilter`
2. **`IOwnershipAuthorization`** (Api) — loads member group IDs from DB
3. **`EfAppDataStore`** — filters load/save to accessible entities only

### Security Semantics

Unauthorized mutation attempts return **404 Not Found** (not 403) to avoid leaking resource existence. Applies to category/link archive, restore, favorite, create in inaccessible groups.

### ContentOwner Resolution

`ContentOwner.TryResolve(ownerType, ownerGroupId, …)` validates create requests:

- `ownerType=Group` without `ownerGroupId` → **400 Bad Request**
- Non-member group → **404** on create and name-available checks

### Home Content Filter

`HomeContentFilter` enum: `All`, `Mine`, `Shared`. Applied in `MealDataQueries.GetActiveCategories` / `GetFavoriteCategories`.

### Group API

- `POST /api/groups` — create group; creator becomes Admin member
- `GET /api/groups` — list groups for current user
- Invite/join UI deferred to E5

### Legacy Backfill

`OwnershipBackfillService` at startup assigns orphan rows (both owner columns null):

1. Categories → default/earliest user
2. Links → inherit parent category ownership via SQL join

### Key Types

- `OwnershipRules`, `IOwnershipAuthorization`, `OwnershipAuthorizationService`
- `ContentOwner`, `HomeContentFilter`, `GroupSummary`
- `GroupEndpoints`, `OwnershipBackfillService`
- `MealCategoryEntity`, `MealLinkEntity`, `GroupEntity`, `GroupMembershipEntity`

## API Surface

All routes require authorization unless noted. Prefix: `/api`.

### Auth (`AuthEndpoints`)

| Method | Route | Description |
|--------|-------|-------------|
| POST | `/auth/register` | Create account |
| POST | `/auth/login` | JSON login (rate limited) |
| POST | `/auth/logout` | Clear session |
| GET | `/auth/me` | Current user info |

### Bootstrap (`BootstrapEndpoints`)

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/bootstrap` | Full scoped `AppData` snapshot |

### Categories (`CategoryEndpoints`)

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/categories` | Active categories (`?filter=All\|Mine\|Shared`) |
| GET | `/categories/favorites` | Favorite categories |
| GET | `/categories/archived` | Archived categories |
| GET | `/categories/name-available` | Duplicate name check (scoped by owner) |
| GET | `/categories/{id}` | Single category |
| POST | `/categories` | Create (`name`, optional `ownerType`, `ownerGroupId`) |
| POST | `/categories/{id}/archive` | Soft delete |
| POST | `/categories/{id}/restore` | Restore from archive |
| POST | `/categories/{id}/favorite` | Toggle favorite |

### Links (`LinkEndpoints`)

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/categories/{id}/links` | Active links in category |
| GET | `/categories/{id}/links/favorites` | Favorite links |
| GET | `/categories/{id}/links/archived` | Archived links in category |
| GET | `/links/archived` | All archived links |
| POST | `/categories/{id}/links` | Create link (inherits category ownership) |
| POST | `/links/{id}/archive` | Archive link |
| POST | `/links/{id}/restore` | Restore link |
| POST | `/links/{id}/favorite` | Toggle favorite |
| PUT | `/links/{id}/preview` | Store OG preview metadata |

### Groups (`GroupEndpoints`)

| Method | Route | Description |
|--------|-------|-------------|
| POST | `/groups` | Create group |
| GET | `/groups` | List user's groups |

### Settings (`SettingsEndpoints`)

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/settings` | Read app settings |
| PUT | `/settings` | Update culture code |

### Link Preview (`LinkPreviewEndpoints`)

| Method | Route | Description |
|--------|-------|-------------|
| GET | `/link-preview?url=` | Fetch Open Graph metadata (SSRF guarded) |

## Blazor UI

### Render Modes

| Page | Mode | Notes |
|------|------|-------|
| `Home.razor` | `InteractiveServer` | Heavy forms; server circuit |
| `Category`, `Share`, `Archive` | `InteractiveAuto` | Server first, may hydrate WASM |
| `Register.razor` | `InteractiveServer(prerender: false)` | Avoid auth mismatch |
| `Login.razor` | Static SSR | Plain HTML form, no `@rendermode` |

### InteractiveShell Gate

`InteractiveShell` blocks child content until:

1. User authenticated
2. `ApiMealDataService.InitializeAsync()` completes
3. `CultureService.InitializeAsync()` completes

Subscribes to `ApiMealDataService.Unauthorized` → redirect to `/login`.

### Localization

- Server: `UseRequestLocalization` (en, ar)
- Client: `CultureService` persists culture via `/api/settings`, sets RTL via JS interop
- Strings: `LocalizationCatalog` keyed by culture

### Component Patterns

- Pages inherit `LocalizedComponentBase` for `L["Key"]` accessor
- `CategoryCard` / `LinkCard` encapsulate favorite/archive actions
- Owner picker on Home/Share: personal vs group dropdown

### Client DI (`ClientServiceCollectionExtensions`)

Registers `ApiMealDataService`, `GroupClient`, `AuthClient`, `LinkPreviewClient`, `CultureService`, named `HttpClient "MealDataApi"`.

## Known Tradeoffs & Gaps

| Topic | Current Behavior |
|-------|------------------|
| Client reload | Full bootstrap reload after every mutation (simple, not granular) |
| Client 409 handling | Exception thrown; no automatic retry UI |
| Settings path | `SettingsEndpoints` writes directly, not via full `AppData` snapshot merge |
| Group join | API-only; no invite UI (E5) |
| OpenAPI | No Swagger; use this doc + endpoint source |
| README | May lag behind E3+ ownership; trust L1/L2 |
